# Big Rig Rumble

A Mario Party-style 3D board game with trucks, built as a single self-contained HTML page.
three.js r128 (UMD from cdnjs) + ConvexHull/ConvexGeometry (jsdelivr), no build tools, no framework.

## Build
`sh build.sh` concatenates the parts in `src/` into two files in `dist/`:
- `dist/index.html`: the **web version**. Multiplayer via PeerJS (the host's browser is the hub). Deploy anywhere (Netlify).
- Deploy the web version: `npx wrangler deploy` (wrangler.toml, worker `bigrigrumble`, serves `dist/` minus `.assetsignore`).
- `dist/claude-artifact.html`: the **Claude artifact version**. Multiplayer via Claude's `window.claude.use("room")`.
Both share almost all code. Always edit files in `src/`, then rebuild. All parts go into ONE `<script>` (the parts after part1 are plain JS continuing that script; part4c/part4cn close it).

## Source map (src/)
- `part1.html` / `part1n.html`: head, all CSS, opening `<script>`. `n` = web version (adds PeerJS script tag).
- `part2.js`: constants, TRUCKS (12 trucks + dice), 2D board layout for the classic map, GFX core (renderer, materials `M()`, `mesh()`, `B()` box, `Cy()` cylinder, lights, ground, trees, showroom, podium, dice, camera, frame loop).
- `partart.js`: embedded artwork as data URIs (generated from `art/`; regenerate rather than hand-edit). `MIKE_ART` = Magnet Mike anime portrait used in the countdown sticker (`showMike` in partfx).
- `parttruck.js`: `buildTruck(i)` Kenney-style truck models, per-truck animations (`animTruck`), `chamferBox` (all edges bevelled) and `chamferBoxSq` (bevel with chosen square sides, via ConvexGeometry).
- `partmap.js`: board maps as graphs (`MAPS.classic`, `MAPS.junk` Junkyard Jumble with forks, conveyors, crushers, Magnet Mike rival), board 3D builder, tokens, camera controls (drag/pinch/twist + WASD), keyboard handling. `MAPS.volcano` Volcano Quarry: the board is a volcano crater. Rim road (`rim`, y 8) on the crater lip, the outer cone (`CONE`, `coneY`) falls to a plain far below; inside, every road segment is its own rock causeway (`prismGeo`) standing in the lava lake, gravel with tyre ruts and instanced pebbles, so lava shows between ledges. Ledges wind smoothly down (`arc` interpolates radius and height): upper `sl` (7→5), lower `lv:2` (~4→3), crater floor `lv:1` (~1), rock-conveyor bridge `br`. Map props `dice: 1.5` (all die faces ×1.5 via `mulFaces`, shown on the map button), `lava`, `size` (camera scale), `camY`. Lava cycle 7 rounds (`lavaLv`/`lavaPh`/`flooded`): low 3, rising 2, high 1, eruption round; `lavaRound()` at round start pushes trucks uphill (−3), `eruption()` (phase `erupt`) makes `HG.obs` obsidian spaces and launches crater trucks to the rim. New space types `OB` (obsidian, +2 shards), `SD` (shard space, +1), `MC` (pillar minecart: `HG.cart {pid, at, boom, n}`, `buildCartRails`/`cartCurve` one open track (spur from the space, one climbing turn round the pillar, into the crystal), the cart rides up and back down; smashing the crystal gives `BIG_SHARD` 15; `HG.bigShard` false until the next round, the crystal (`bd.crys`) regrows in `stepCart`), `MR` (rail cart, 3 spaces: `railRide`/`railPath` random 8–14 space run along the roads then the quickest way home, picking up loose shards; `HG.ride` shows `bd.rideCart` under the truck), `GY` (geyser; lands on `gyTarget(i)` = `HG.gyT[i]` re-rolled every round by `rollGeysers()`, default `n.gy`; arcs re-aim via `aimGy`). Rising lava throws loose shards out of the lava lake (6 at the first level, 10 at the second; they fly in arcs via `userData.fly`) (`HG.loose`, `scatterShards`, picked up when driving over them in `afterStep`, cleared when the lava drains); the eruption's 14 lava bombs land anywhere off the crater and also leave loose shards (no more obsidian tiles from bombs). No carry limits (`SHARD_MAX`/`DUST_MAX` 999). `obsidianMesh(k)` = two hexagonal crystals (`xtalGeo`) like the tile icons, used for every shard model. Shop item `grinder` (Portable Grinder, 20, shard maps only via `itemHere`). Steps-left badge over the moving truck: `stepBadge`/`stepBadgeFor` (gold coin, number on a canvas cap texture). Refineries are not a space type: `n.ref` marks a normal blue space with a refinery gate over it. No tolls (removed). **Shard economy** (map prop `shards`, rules in partgame `SHARD_MAX`/`CELL_MAX`/`CELL_SHARDS`/`CELL_COINS`/`RAW_PRICE`, `shardMap()`): players carry `p.shards` (max 5) and `p.dust` (obsidian dust, max `DUST_MAX` 6). Shard spaces give +1, obsidian +2 (`addShards`, overflow lost with a "Truck bed full!" sticker). Driving onto or past a `ref` space with shards stops the truck: `HG.grind {pid, at, k, n}` plays `stepGrind` (shards sucked up, gate shakes, dust spat onto the truck) and after 3 s `refine` turns each shard into 1 dust. Battery: the factory melts `DUST_BAT` (5) dust + 10 coins, or 50 coins (`resolveBuy(yes, seq, how)`, act `{t:"buy", how: "cell"|"coins"}`, `canDust`). Flooded landing (Scorched −5) and being pushed uphill by rising lava each cost a shard (`loseShard`; armor protects). CPUs: `botDist` steers to the crater while < 3 shards, then the nearest refinery, then the factory once they hold 3 dust (pay 50 only with `RAW_PRICE + BOT_RICH` coins or in the last round). Map prop `rules` lists the map's rules in the lobby (`mapRulesHTML`). Refineries (rim[25], U1[2], L2[3]; L2[1] sat under the bridge): `geoRefinery(halfRoad, side)` is a drive-through gate across the road (tank pylon on the lava side, stone tower with steam stack opposite, girder + hot pipe across, double-sided shard → cell sign, intake funnel, faint purple suction cone with air streaks spiralling up, `userData.tick`; `userData.node/base` for the grind shake), turned with the road; editor prop id `ref<space>`. Batteries/battery icon are purple here (`batteryMesh()` → `BAT_LOOK.v`, `bIco()`). Also `signBoard(txt, {style, w, h, col})`: double-sided 3D title signs (styles wood / barn / neon / race) used for JUNKYARD, GARAGE, DRIFT KING and DRIFT RACE; prefer it over flat `textSprite` for titles.
- Battery factory models (partmap, `FAC_MODELS`, `FAC_LOOK = {def, volc}` picks which one each style uses): `works` (Battery Works: brick-based ribbed hall, glazed sawtooth roof, office annex, acid tanks, banded chimney, roll-up door, battery conveyor), `plant` (cooling tower, giant battery hall, transformer yard, pylon), volcano `forge` (basalt hall, glowing sawtooth roof, furnace mouth + lava crucible, ember chimney, purple-battery conveyor) and `reactor` (dome with purple bands, floating obsidian crystal). Each returns `userData {sign?, puff, puffs, tick}`; helpers `sawRoof`, `facBelt`, `batSign`. Volcano ones carry the hot pipe into the lava.
- Tile faces are pressed in (`tileFace(t, sides)`, cached in `FACE_GEO`): the top plate (y .42–.50) has the symbol cut through it (`symHoles(t)`: holes built from `strokeShape(pts, w)` + `arcPts`, `polyShape`, `discShape`; holes must never touch, so draw symbols as separate pieces or one outline) over a darker floor at y .44 (`SYM_FLOOR` overrides). `SC` is a shovel, `S` a start flag on a red floor, `GY` a crater rim around a dark vent with mist, `OB` two tilted shards on a lilac floor. Things on a tile's top must sit above y .50.
- Test mode (lobby toggle `HG.test`): on your turn `testHTML` offers exact rolls (act `troll`), "Jump to a space" (tap the board, `GFX.jumpPick` + `pickNodeAt`, act `tjump` lands and triggers the space), and top-ups (act `tgive`: coins, shards, dust, next lava round). Loose shards are one big upright crystal.
- Routes: at any crossing a truck may take any road, also against the usual direction, except straight back (`travelOpts(i, p.from)`, `p.from` = space it arrived from, cleared on teleports). Distances use `routeDist(from, to, target)` / `playerDist(p, t)` (not `MAP.F`); fork buttons named by `roadLabel`. Factory spots must clear all roads (`facSpot(i).ok`, footprint `FAC_FOOT`). Free camera keeps the follow target height (`GFX.ov.ty`).
- `partfx.js`: sky gradients, per-face colour variation, particles (`burst`), synthesized sound (`sfx`), board effects.
- `partnet.js`: PeerJS networking adapter that imitates the Claude room API (web version only).
- `part3.js` / `part3n.js`: identity, host engine core (`push()` broadcasts state `HG`), client join, views (home, join, lobby, game HUD). `n` = web version (code-based joining, QR with `?join=CODE`).
- `partgame.js`: game rules (turns, dice, items shop, upgrades, duels, teams, forks, Magnet Mike), board UI panels, practice menu.
- `part4a.js`: live 3D minigame engine (`start3D`, `stepMG`, arena physics, ramming + loot drops, networking of minigame state, HUD, ready screen, themed tap controls).
- `part4b.js`: the 12 original minigames (`MG` object). Some keys kept their old id but were reworked: `hill` = Fire Brigade, `light` = Red Light Green Light (lorry), `hop` = Rush Hour, `park` = Dump Run, `tiles` = Concrete Crumble (wet cement), `bumper` = Mud Brawl, `rocks` = crane slab over a quarry. Also shared helpers `grandstands()` / `crowdMeshes()` / `crowdStep()` (instanced cheering crowd) and `engineSnd()`.
- `partmg2.js`: truck-special minigames: Scoop Stack, Sort It Out, Taco Tower, Tow Rescue, Drift King (Zoomer, `drift`) (`Object.assign(MG, ...)`), plus the regular arena game Drift Race (`race`: one ~820 m lap on a 3D Catmull-Rom spline `PTS [x,z,y]` with a flyover roundabout (bridge over its own entry road), hill tunnel, hairpin and crest; hold-DRIFT Mario Kart-style mini-turbos with blue/orange/purple charge; bridge deck and tunnel hill fade see-through when your truck is underneath. Slipstream: 1.2 s within 9 m behind a truck gives a white boost (`e.f.bl = 4`). Ram tuning per game via `ramK` / `ramSelf` / `ramSlide` / `ramKeep` / `canRam(e)` (race: drift boosts ram softly, slipstream boosts never ram). Samples carry `over`/`under`/`tun` flags; trucks at different heights skip collisions; `e.pitch` tilts trucks on slopes). Shared `driftPhys()` handling for both drift games.
- `partedit.js`: PC map editor (home button "🛠 Map editor", `FINE` pointer only; `GFX.mode = "edit"`, own camera + OrbitControls/TransformControls lazy-loaded from jsdelivr). Edits per map `{p: shape params, n: {space: {x,y,z,r,s}}, o: {prop: {p,r,s}}}` live in localStorage `trp_mapedit`; `buildBoardFor` calls `applyMapEdits(map)` (merges `map.bake` + localStorage, moves nodes, sets `LAVA_Y`), shape params via `ep(key)` (table `ED_PARAMS` in partmap), selectable props via `edReg(obj, id)`. To bake the user's "Copy edits" JSON: set `MAPS.<id>.bake = {p, n, o}` in partmap (node edits are absolute positions; `r` = extra yaw on top of the automatic road-following yaw from `tileGroup`).
- `part4c.js` / `part4cn.js`: click handlers, boot, closes the script.

## Architecture notes
- Host-authoritative: the host holds `HG` (game state) and broadcasts it as presence `game`. Clients send actions via presence `act` (`{t, seq, id,...}`), host applies in `handleAct`. `G` = the state being viewed (host: `G === HG`).
- Minigames: each device simulates its own truck; the host (or `mg.simDev`) simulates CPU trucks and sends all bot scores in one `act({t:"mg", bots:{...}})`. Minigame defs: `kind` (`arena` | `lane` | `station`), `ctrl` (`stick` | `tap` | `custom`), `dur`, `hi`, `build/spawn/rules/bot/render/cam/tick/final/prompt/botScore`, custom controls via `ctlHTML()` + `wire()` + `onKey()`.
- Practice mode: `HG.practice = true`, never broadcast, never saved.
- TV mode (web only, "Host on a TV"): `HG.tv = true`, the host has no player of its own. Body class `tv` on the host (big lobby `tvLobbyHTML`, zoomed HUD, `tvPanelHTML` status line); body class `ctl` + `GFX.ctl` on phones in the game view (3D board hidden and not rendered, `ctlMeHTML` card, big buttons). The first human (`tvLead`) can add CPUs and start via acts `addcpu`/`start`. TV minigames (`tvPlayable(g)`: arena + stick, not `race`) set `mg.tv`: the TV runs one simulation of every truck (`start3D(mg, null)` → `W.tv`; humans are `e.rem` + `e.isMe` with their own `e.inp`), framed by `tvCam`. Phones open `openTvCtl` (`TVC`, stick + RAM only): they send presence `rin {n,k,x,y,b,h}` on the minigame room (`b` = RAM press counter), the TV sends `tvs {n, l:{key:[score, cd, ramReady, done, msg, place, dropT]}}`, and `tvSubmit()` writes every score straight into `HG.mg.res`. All other minigames use `mg.tv = "split"` (`openTvSplit`, `TVS`): the TV builds one world per human (exactly what that phone would have simulated: `start3D(mg, p, false, null, {simK})`, `W.split`), and the worlds sync through `W.out` instead of the network (`netRecv`/`netApply`). `tvsFrame` swaps the globals (`W`, `GFX.cam`, `GFX.mgCam`, `GFX.w/h`) per world and toggles `data-hid` ids (`tvsAct`) so `$("#m3c")`-style lookups hit that world's HUD and controls. Layouts (`TVS.mode`): `grid` (station games, scissor viewports), `shared` (lane games: one wide view of world 0 framing all lanes + player cards), `dyn` (Drift Race with 2 humans: per-player chase cams blended toward a shared cam as they get close; world B rendered to a render target and composited behind an angled divider). Phones show the game's real controls (`ctlHTML`/`tapCtlHTML`); button presses go as `rin.ev [[seq, buttonIndex, down]]` and are replayed as pointer events on the TV's hidden copy; the TV's copy is mirrored back (`mirSnap`/`mirKids`, `tvs` field 7). The background-tab fallback interval in part4c(n) must call `tvsFrame` when `TVS` is set. In practice, a 💡 chip in the minigame top bar opens `wireLightPanel()` (part4a): live sliders for ambient/sun/sun height/angle/warmth/haze; the user copies the values line and asks for them to be made permanent per game. Its Effects tab drives optional post-processing (`GFX.fx`, `renderMG()` in part4a): SSAO, UnrealBloom, tilt-shift, vignette, hue/saturation + contrast, FXAA, using r128 examples/js scripts lazy-loaded from jsdelivr on first use; sprites/points/lines are hidden during the SSAO normal pass. Minigames render through `renderMG` (plain render when no effect is on).
- Board popups: `showEvent` → `showSticker` (navy sticker with icon badge, `EV_LOOK` maps titles to icon/tone) and `showMike` (MIKE_ART). They go through `stickerShow()`, a queue on their own `#fxs` layer (STICKER_MS each), so `fxShow` dice labels can't wipe them; skipped on TV-mode phones (`body.tvphone`). Magnet Mike strikes every `RIVAL_EVERY` (3) rounds; `rivalNote()` shows the countdown and sets `HG.hold` (rolls/items blocked, CPUs wait) until the sticker is gone; `HG.intro` does the same during the opening flyover.
- TV extras: `tvPractice(g)` plays one minigame from the TV lobby (`mg.prac`: no coins, back to the lobby); phones in TV games get `#rotov` ("turn your phone sideways" while portrait, iPhone Safari Hide Toolbar tip) and a landscape controller layout; Android tries fullscreen + landscape lock (`tvcLand`). Last-truck-standing games give the winner a 3 s victory lap (`W.lsT`, `e.won`).
- Minigame environment flags (read in `mgEnv`/`stepMG`): `bare` (no default grass/water/mountains, build your own ground), `night`, `storm`, `dusk` (sky + light presets), `water:false`, `sun:[x,y,z]` (sun offset), `fallY` (depth before a falling truck is hidden). Optional hooks: `phys(W,e,inp,dt)` replaces the default arena physics (Drift King: heading + low side grip), `cam(W,tgt,pos,far)` also works for arena games, `ramLabel` / `ramCd(W)` / `ramReady(W)` / `stickHint(fine)` repurpose the RAM button (Drift Race DRIFT); `W.inp.hold` is true while the RAM button or Space is held, bots return `hold` too, `stop(W)` cleanup, `donePrompt(W,e)` message after finishing. `camFov()` sets the minigame FOV (reset automatically).
- Anything random that must match across devices comes from `W.rng()` (seeded) or a pure function of `W.t`; `Math.random()` only for cosmetic effects.

## Gotchas already learned (don't repeat)
- **Z-fighting/flicker**: never place two surfaces at the same height or within ~0.02 of each other. Decals: `depthWrite:false` + `polygonOffset`. Stripes on bevelled bodies must stick out ≥0.025 per side. Overlapping blocks: make one slightly narrower or offset.
- **`.visible` must be a real boolean**: three.js only hides when `visible === false` (null/undefined still renders). Use `!!`.
- **Entity field names**: in minigames `e.k` is the player key. Never reuse `k`, `i`, `p`, `sc`, `d`, `al`, `c`, `f` for game-specific data (Taco Tower bug).
- Published Claude artifacts can only load scripts from cdnjs/jsdelivr/unpkg-free list; no remote images/fetch.
- Frame-rate independence: timing uses real time (physics substeps, podium/intro use `performance.now()`).
- Reduced motion: infinite CSS animations must also get `animation-iteration-count:1`.
- **Never put a `//` comment mid-line**: much of the code is long one-line statements, and a `//` comments out the rest of the line (this broke the build three times). Syntax-check the built script after every build, e.g. `new Function(<script contents>)` in node.
- `obj.add(x)` returns `obj`, not `x`: `s.add(mesh).position.set(...)` moves the whole scene.
- On Windows `python` may be the Microsoft Store stub and hang; use node for scripts.
