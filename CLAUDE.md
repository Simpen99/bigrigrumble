# Big Rig Rumble

A Mario Party-style 3D board game with trucks, built as a single self-contained HTML page.
three.js r128 (UMD from cdnjs) + ConvexHull/ConvexGeometry (jsdelivr), no build tools, no framework.

## Build
- `sh build.sh` concatenates `src/` parts into `dist/index.html` (web version, PeerJS multiplayer, the host's browser is the hub). Deploy: `npx wrangler deploy` (worker `bigrigrumble`, serves `dist/`).
- All parts go into ONE `<script>`: `part1.html` opens it, the `.js` parts continue it, `partend.html` closes it.
- Always edit `src/`, then rebuild. Syntax-check the built script after every build (e.g. `new Function(<script contents>)` in node).
- JS parts are formatted with Prettier (`.prettierrc`: tabs, width 120). Run `prettier --write "src/*.js"` after editing JS. CSS in part1 stays one rule per line.
- PR descriptions start with a test link for the branch build (the user tests on an iPhone): `https://raw.githack.com/Simpen99/bigrigrumble/<branch>/dist/index.html`. Commit the rebuilt `dist/` so the link works.
- `.ignore` keeps Grep out of `dist/` and `src/partart.js` (huge one-line files).

## Architecture
- Host-authoritative: host holds `HG` and broadcasts it as presence `game`. Clock sync: devices' clocks can be seconds apart, so the host stamps `HG.clk` (and presence `clk` every second); clients keep `CLK.off` (largest recent host-minus-local sample, `clkSample`) and convert host times with `hostTime(t)` (the minigame start `G.mg.t0` in `syncStart` and on TV controllers). Test: `nettest.mjs <game> --skew 1000` (the phone's clock 1 s ahead; it reports the game clocks' difference). Clients send presence `act` (`{t, seq, id, ...}`), handled in `handleAct`. `G` = state being viewed (host: `G === HG`).
- Minigames: each device simulates its own truck; the host simulates CPUs and sends their scores in one `act({t:"mg", bots})`. Defs: `kind` (`arena` | `lane` | `station`), `ctrl` (`stick` | `tap` | `custom`), `dur`, `build/spawn/rules/bot/render/cam/tick/final/prompt/botScore`, custom controls via `ctlHTML()` + `wire()` + `onKey()`. Optional hooks: `phys`, `cam`, `ramLabel` / `ramCd` / `ramReady`, `stop`, `donePrompt`, `tapEarly` (a tap during the countdown, e.g. Drag Race's burnout; `pre(W, e, dt)` runs for local trucks during the countdown, `cd` = countdown seconds, `cdText(t)` = its numbers; tap games also get `W.inp.hold` while the button or key is held); TV controller layouts (players watch the TV, not the phone): `swipe: {l, r, u, d: button index}` + `swipeHint` (swipe pad), `slide: true` + `slideHint` (finger position = `W.inp.x`, flick up = `W.inp.boost`, `wireSlide`; the TV controller puts the slider on the left and a `slideBtn` button, default SERVE, on the right, plus an optional `slideBtn2` = `W.inp.b2` sharing the right side diagonally), `tvHint` (the TV intro's control line), `pad: "<selector>"` (a trackpad element in `ctlHTML`: on a TV controller the finger's spot on it is `W.inp.x` / `W.inp.y` in -1..1, absolute, lifting = `W.inp.boost`; `wirePad`), `tvcOpen(api)` = the game draws its own view on the controller (`api.wrap`, `api.col`, `api.put(x, y)` = a pad spot + lift; returns a cleanup function); `ctlPhases: true` = the controls switch layout on purpose (tvtest then doesn't flag it); `clock(W)` = the top chip's text instead of the seconds left (round-based games); `aim: true` (stick games) swaps the RAM button for a second stick on the right half (input `ax` / `ay`, arrow keys on a keyboard, sent by TV controllers too) and disables ramming (Fire Brigade's hose); `W.camShift = [x, y]` (set from `cam`, shares of the screen) shifts the picture with a view offset instead of turning the camera (Plinko Sabotage frames the target's board square on beside its tray); env flags `bare`, `night`, `storm`, `dusk`, `water:false`, `sun`, `fallY` (read in `mgEnv`). The light panel's Save button stores its values per game on that device (localStorage `trp_light`, applied by start3D over the baked ones; Default drops them). Baking the light panel's Copy line: `sun: [x, height, z]` (angle at distance ~18.4), `lt: {amb, sun, warm, haze}`, `fx: {ao, bloom, tilt, vig, col, aa}`.
- New look (trial on `cones`, `park`, `sort`): `def.look = {exp, amb, sun, warm, env, haze, glow, bloom, fill, sky}` (defaults `LOOK0` in part4a, applied by `applyLook`). Scenes with `userData.lk` render with sRGB output + ACES (`gfxLook`, called from a wrapped `GFX.r.render`); `lookShaders()` (part2) patches three's shaders to read colours/textures as sRGB only when `TONE_MAPPING` is defined, so classic games are untouched. Light colours in look scenes must be linear (`convertSRGBToLinear`). Emissive glow goes into alpha for the emissive-only bloom; RoomEnvironment via `lookEnvTex()`.
- Team minigames: `def.team = "1v3" | "2v2"`. At the end of a round `spaceSplit()` (partgame) gives each truck the side of the space it stands on (B = blue, R = red, other spaces a coin flip; 4+ trucks, not in board team mode); a 1 vs N or 2 vs 2 split shows the `HG.phase = "teams"` reveal sticker (`showVs`) and picks from that pool, otherwise (or if that pool only holds the last game) free-for-all. `HG.mg.team / tm {key: side} / tc [colours]`, side 0 = the solo truck; `e.side` on entities, side 0 spawns first; discs and tags take the side colour. Payout `finishTeamMg`: `def.teamWin(res, tm)` → 0 | 1 | -1, winners get `TEAM_WIN` each. Hooks: `teamHow(side, solo)`, `fmtTeam(v, side)`, `fmtE(W, e)` (live board), `botScore(side)`. Practice picks the split with `forcedSplit`. Per-truck physics fields: `e.rad`, `e.mass`, `e.ramM`, `e.spd`, `e.ramCdT` (collide / arenaPhys).
- Random values that must match across devices: `W.rng()` or a pure function of `W.t`. `Math.random()` only for cosmetics.
- Practice mode: `HG.practice = true`, never broadcast or saved.
- Linked big screens ("Join as a big screen"): a device joins a big-screen game as a screen (`screenJoin`, `SCREEN = {key, acts}`, no player of its own; `tvView()` = this device shows the big-screen view, host or screen; its lobby `screenLobbyHTML` shows its own QR with `&hub=<screen key>`). Phones that join through it carry `me.hub` and the host stores `p.hub`. With any linked screen in the game every minigame runs one world per player (`mg.tv = "split"`, no single TV simulation), each screen opens worlds only for its own players (host: no `hub`), the CPUs run in the `simDev` player's world, screens share their worlds as presence `rts` (`TVS.hubs`) and read the others' in `netRecv`; a screen's results reach the host through a queue of acts in its presence (`acts`, each act's `for` = the player key, accepted only for players on that screen). Test: `tvtest.mjs <game> --screen`.
- TV mode: `HG.tv = true`, host has no player; body class `tv` on the host, `ctl` on phones. Stick arena games run as one simulation on the TV (`W.tv`); all others run as one world per human on the TV (`mg.tv = "split"`, `TVS`). The background-tab fallback interval in part4c must call `tvsFrame` when `TVS` is set.
- `HG.hold` / `HG.intro` block rolls and items (and make CPUs wait) while a sticker or the intro flyover plays.
- Routes: trucks may take any road at a crossing except straight back (`travelOpts(i, p.from)`). Distances via `routeDist` / `playerDist`.
- Performance: static board parts are merged (`mergeStatic`, tag `userData.st`, skip `userData.dyn`). Minigames: `mergeScene(W)` (end of `start3D`) merges static scenery per material into one mesh per 32 m cell. Static = not reachable from `W` or the def, no `userData` on it or a parent, opaque, visible, no children; so anything a game moves, shows or recolours later must be kept in `W` (or get userData). `def.noMerge` opts out. `tools/run.mjs` reports merged meshes that changed anyway (NOT STATIC). `bakeKit` and the trucks put plain materials onto shared white ones with the colour in the vertex colours (`neutralMat`): don't recolour a shared `M()` material at runtime expecting baked props to follow. The post chain ends in one combined pass (`finalShader`: FXAA + saturation/contrast + vignette). Board shadows only re-render when `shadowCheck` sees a caster move: add new moving shadow casters there. Phones (`GFX.touch`) use no log depth buffer and a 1024 shadow map.
- Volcano map: lava cycle (`lavaRound`, `eruption`), space types `OB` `SD` `MC` `MR` `GY`, shards → refinery (`n.ref`, `HG.grind`) → dust → battery at the factory (`resolveBuy`). Loose shards `HG.loose`. Map props `dice`, `lava`, `shards`, `rules`, `size`, `camY`.

## Gotchas (don't repeat)
- **Z-fighting**: never put two surfaces within ~0.02 of each other. Decals: `depthWrite:false` + `polygonOffset`. Stripes on bevelled bodies stick out ≥0.025 per side. Things on a tile's top sit above y .50.
- **`.visible` must be a real boolean** (`!!`): three.js only hides on `=== false`.
- **Minigame entity fields**: `e.k` is the player key. Never reuse `k`, `i`, `p`, `g` (the truck's group), `tr`, `sc`, `d`, `al`, `c`, `f` for game data.
- **Never put a `//` comment mid-line**: it comments out the rest of the line.
- `obj.add(x)` returns `obj`, not `x`.
- Tile symbol holes (`symHoles`) must never touch each other.
- Frame-rate independence: use real time (`performance.now()`, physics substeps).
- Reduced motion: infinite CSS animations also need `animation-iteration-count:1`.
- On Windows use node for scripts, not `python`.

## Testing
Use the scripts in `tools/` (see `tools/README.md`; `cd tools && npm i` once, then `sh build.sh` before running):
- `node tools/check.mjs <models>`: automatic model checks (z-fighting, overhanging panels, floating and buried parts), problem parts in magenta. **Run it on every new or changed model and fix what it finds.**
- `node tools/rig.mjs <models>`: a model from front, back, side and 3/4 above; look at it before shipping.
- `node tools/sheet.mjs <games>|all [--landscape]`: minigames at iPhone size on one contact sheet.
- `node tools/run.mjs <games>|all`: play minigames to the end and report page errors.
- `node tools/watch.mjs <game> [--runs N --quiet --as human --side 0 --film]`: watch a minigame play out (play-by-play log, results, win and knockout-cause summary). **Use it for any tuning or "why does X happen" question instead of writing one-off scripts.** Games log events with `mgLog(W, text)` and set `e.lastHit = {k: cause, t: W.t}` when they knock a truck; optional `def.watchSum(W)` (one summary line) and `def.humanBot` (plays like a person, for `--as human`).
- `node tools/nettest.mjs <game> [--lag 120 --solo phone --cpu N --log]`: two-device multiplayer test (host + phone in two headless browsers joined by code through a fake PeerJS relay, no internet). Reports position drift, knocked-out state that disagrees, results that differ, missing scores, stuck screens, page errors. Shared game state: `def.syncSnap(W)` returns a plain value (must match, mismatches over 3 s count) or `{key, state}` (state must match whenever the inputs `key` match); shared events log `sends KEY` / `got KEY` via `mgLog` and get their delivery time measured. Run it on any game whose multiplayer sync changed.
- `node tools/tvtest.mjs <game> [--phones N --cpu N --lag 80 --ready]`: TV mode (TV + phones as controllers, fake relay). Contact sheet of every screen, and reports trucks hidden under the intro card / ready panel on the ready screen (`--ready` = only that check, quick to loop over all games), controller layouts that change mid-game (e.g. the TV's control mirror overwriting the phone's own layout), buttons off screen / too small / overlapping, trucks off the TV screen and their size there, stuck screens, page errors. **Run it on any change to TV mode or the TV controller.**
- `node tools/ctlsheet.mjs [games]`: TV mode phone controllers on one sheet (each game a few seconds in, iPhone landscape; runs `tvtest.mjs --early` per game).
Models are presets (`cars`, `taxi`, `houses`, `trucks`) or JS expressions returning an Object3D, facing -z (`faceZ(m)` turns +x-facing ones). Console hooks: `startPractice("taco")`, `W` (minigame world), `HG` (host state).
